# pause_before は、本当にその長さの間になるか

同じ行（`明日、また来るね`）・seed 1・beta 0.7 を、間だけ **0.0 / 0.3 / 0.6 / 1.0 / 1.5 秒**
で並べた 6 本（最後にもう一度 0.0 を置いて、0 のときの床を見る）。焼いたあとの WAV を
20 ms 枠の RMS で読み、**−50 dBFS を切った区間の長さ**を測った。

## 結果

| 書いた `pause_before` | 焼いたあとの無音 | 差 |
| --- | --- | --- |
| 0.0 | 0.08 秒 | +0.08 |
| 0.3 | 0.38 秒 | +0.08 |
| 0.6 | 0.68 秒 | +0.08 |
| 1.0 | 1.08 秒 | +0.08 |
| 1.5 | 1.58 秒 | +0.08 |

## 読み

- **書いた値は、そのまま間になる**（5 段で同じ +0.08 秒）。差は一定なので足し引きで消える
  ——5 段のあいだの差は 0.30・0.30・0.40・0.50 秒で、書いた値の差と一致する。
- **+0.08 秒の正体は `assemble.py` の切り残し**（頭 0.02・尾 0.06 秒）。WAV の頭尾の
  無音は −50 dBFS で切るが、切った境の 0.02 / 0.06 秒は残すので、無音として 0.08 秒見える。
- **0 のときも 0.08 秒空く**。台詞を地続きにしたいなら 0.0 でも 0.08 秒の隙が入る、
  と覚えておく（聴いて分かる長さではない）。
- 行の中の読点のあとに **0.30 秒**の間がある（どの本でも同じ）。これは `pause_before`
  ではなくモデル自身の読みで、`pause_before` の値には依らない。ただし読点を**増やしても
  積み上がらない**（[`experiments/delivery/acting-pauses/`](../acting-pauses)・2 個で +5 ms・3 個で −195 ms）。
